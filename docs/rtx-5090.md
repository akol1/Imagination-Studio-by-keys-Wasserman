# Imagination Studio on a 32 GB card (RTX 5090)

Video runs on a 32 GB GeForce RTX 5090 with 91 GB of system RAM. The installer asks for a 96 GB card by default, so
this is an opt-in: nothing changes unless you set the variables below. The clips below were rendered with the
TensorFold CUDA engine (`engine: cuda (TensorFold int8 blocks in ComfyUI, sparse attention 0.8)` in the app log): the
transformer blocks run on TensorFold in int8, and ComfyUI hosts the rest. The guard budgets the machine's RAM instead
of the card's memory. Where the int8 blocks sit during a render was not logged, so no streaming path is claimed for
this route. Measured on one machine only; nothing smaller than 32 GB was tried.

## What you need

| | Notes |
|---|---|
| GPU | NVIDIA RTX 5090, 32 GB (sm_120). |
| System RAM | 91 GB was used. The guard budgets RAM (see `STUDIO_ROOM_MB`), so more RAM means more room. |
| Driver and CUDA | Measured on NVIDIA driver 610.43. `nvcc` 12.9 or newer. The engines did not build with a 12.8 `nvcc`; point `NVCC` at a newer one if the system default is older. |
| The rest | As in [docs/rtx-pro-6000.md](rtx-pro-6000.md): x86_64 Ubuntu, `git`, `ffmpeg`, `curl`. |

## Install and run

```bash
export NVCC=/usr/local/cuda-13/bin/nvcc   # nvcc 12.9 or newer; an example path
export STUDIO_ALLOW_SMALL_VRAM=1          # installs video on a card under 90 GB
bash oneshot-setup-rtx-6000.sh            # then the same four values as in docs/rtx-pro-6000.md

export STUDIO_ROOM_MB=84000               # the RAM budget of a render, in MB
export SPARK_MEMORY_FLOOR_MB=6000         # optional: the RAM the guard keeps free (default: a tenth of the machine)
bash scripts/app.sh
```

- **`STUDIO_ALLOW_SMALL_VRAM=1`** lifts the installer's 90 GB card floor for video. The 64 GB RAM check stays.
- **`STUDIO_ROOM_MB`** stands in for the card's room in the memory guard (`spark/memory_guard.py`). Without it the
  guard takes the smaller of the RAM and the card, and a 32 GB card refuses the video route. With it the guard uses
  your number, but never more than the RAM that is available, so a too-large value cannot let a render take the
  machine down. Pick about the RAM you can spare: total RAM minus what the desktop and other programs hold, minus the
  floor. Unset, empty or not a number, it is ignored.
  With it set, the guard does not look at the card at all, so it does not see VRAM that another program holds (a game,
  a second model server). Free the card before a render.

## Character Swap on a 32 GB card (4.1.1)

The swap holds MiniMax H3 Ref2VA, SAM 3.1 and the anchor's picture model: about 50 GB on a card that keeps them all.
Without `STUDIO_ROOM_MB` a 32 GB card refuses it before it is queued, naming the card and `STUDIO_ROOM_MB`. With it,
ComfyUI keeps the models in RAM and streams them to the card, and the swap runs. Measured on a DGX Spark under a CUDA
MPS limit of 32 GB with `STUDIO_ROOM_MB=84000`, a 5 s part of an 864x480 clip, int8 Ref2VA, from a stopped ComfyUI:

| Quality | Without `STUDIO_ROOM_MB` | With it: on the card | The machine fell by | Time (a GB10's) |
|---|---|---|---|---|
| Fast (480p) | refused | 32.1 GB (the limit) | 37.8 GB | 349 s |
| High (768p, 1376x768) | refused | 32.1 GB (the limit) | 39.5 GB | 800 s |

On that Spark the card's share is in the machine's fall (one pool), so the guard's figure (`SWAP_OFFLOAD_ESTIMATE`)
holds a card's own RAM to more than it uses. The times are a GB10's: a 5090 streaming from RAM is not measured.

YuE2 songs (int8, the PyTorch loop: the TensorFold decode engine is built on a GB10 only) peaked at 16.3 GB on the card
for 30 s. Without `STUDIO_ROOM_MB` the card's room takes songs up to about two minutes; a 300 s song was admitted with
`STUDIO_ROOM_MB=84000` and peaked at 19.9 GB.
